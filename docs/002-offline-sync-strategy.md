Offline Synchronization Strategy & API Contract

## Status

Accepted

## Context

Team 4 (Sub Team: Abdur and Anas) are responsible for the Offline Mode and Personas module[cite: 4]. To ensure emergency responders can operate without connectivity, we need a robust mechanism to queue operations locally and synchronize them when the network returns. The backend must handle duplicates, stale data, and partial failures safely.

## Decision

We implemented a transactional batch synchronization endpoint (`POST /api/sync/batch`) using Optimistic Concurrency Control and strict Idempotency checks.

### 1. Idempotency (Duplicate Prevention)

Every offline operation MUST include a unique `operation_id` generated by the frontend (UUIDv4). The backend records this ID in the `sync_operations` table. If the same ID arrives twice, the backend returns `ALREADY_APPLIED` and skips processing.

### 2. Conflict Resolution (Stale Updates)

To prevent overwriting newer server data with stale offline data (e.g., two people reporting the same missing person with different statuses), we require a `version` field in the payload for `UPDATE` operations. If the client's version is older than the server's version, the operation is rejected with `CONFLICT`.

### 3. Partial Batch Failures

Operations are processed sequentially but isolated via SQLite `SAVEPOINT`s. If one operation contains malformed data, it is rolled back and flagged as `INVALID`, but the rest of the batch is successfully `APPLIED`.

### 4. Frontend API Contract

The frontend Service Worker must send payloads in the following format:

**Request:**

```json
{
  "operations": [
    {
      "operation_id": "uuid-1234",
      "entity_type": "PERSONA",
      "entity_id": "p-100",
      "operation_type": "CREATE",
      "payload": {"nombre": "Juan", "estado": "desaparecido", "version": 1},
      "client_created_at": "2026-08-24T12:00:00Z"
    }
  ]
}
Response:

JSON
{
  "results": [
    {
      "operation_id": "uuid-1234",
      "status": "APPLIED" // Possible values: APPLIED, ALREADY_APPLIED, CONFLICT, INVALID, RETRYABLE_ERROR
    }
  ]
}
```
