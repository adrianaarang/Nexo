# Código abierto — roadmap futuro

El grupo decidió (62,5% de los votos) que abrir el código no es el diferencial
principal del proyecto ahora mismo, sino algo a evaluar según el alcance del MVP.

Cuando se decida abrir el proyecto: revisar `LICENSE` y `CONTRIBUTING.md` en la
raíz del repositorio, y definir un proceso de moderación de contribuciones
externas antes de aceptar pull requests.
